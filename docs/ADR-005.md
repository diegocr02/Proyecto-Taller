# ADR-005 · Proveedor de IA intercambiable con la API compatible con OpenAI (OpenAI, Gemini, Groq)

Estado: Adoptado (registrado a posteriori por ingeniería inversa)   Fecha del registro: 2026-11-27

## Contexto

ADR-003 (v1.1) fijaba Gemini con la librería `google-genai`. El agente necesita *function calling*, y el equipo quería poder cambiar de proveedor si se acababa una cuota o una clave dejaba de funcionar. OpenAI, Gemini y Groq ofrecen el mismo formato de *chat completions* con herramientas.

## Alternativas consideradas

1. **Solo Gemini con `google-genai`**: gratis, pero si la cuota o la clave fallan, el agente se queda sin modelo.
2. **Un SDK distinto por proveedor**: más código y más dependencias.
3. **Un único cliente `httpx` contra la API compatible con OpenAI de los tres proveedores**: mismo código, cambia solo la URL, la clave y el modelo.

## Decisión

Se adopta la alternativa 3 (`PROVEEDORES` en `agente/agente.py`):

| Proveedor | URL base | Modelo por defecto |
|---|---|---|
| openai | `https://api.openai.com/v1` | `gpt-4o-mini` |
| gemini | `https://generativelanguage.googleapis.com/v1beta/openai` | `gemini-2.5-flash` |
| groq | `https://api.groq.com/openai/v1` | `llama-3.3-70b-versatile` |

Selección (`elegir_proveedor()`): `AGENTE_PROVEEDOR` si está definido y tiene clave; si no, el primero con clave en el orden openai → gemini → groq. El modelo se puede cambiar con `OPENAI_MODEL`, `GEMINI_MODEL` o `GROQ_MODEL`.

## Consecuencias

- *Positivas:* cambiar de proveedor no requiere tocar código. La ficha del agente registra que `gpt-4o-mini` fue el más rápido en las pruebas del equipo (1–3 s, según `docs/ficha_agente.md`; **NO VERIFICADO** en esta tarea).
- *Negativas:* **con el `.env` actual, que tiene claves de OpenAI y de Gemini, se usa OpenAI aunque el instructivo hable de Gemini.** OpenAI es de pago. `google-genai` ya no es necesario y se quitó de `requirements.txt` el 2026-11-27.
